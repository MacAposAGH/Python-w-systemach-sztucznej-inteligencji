A. Funkcje i iteratory

Funkcja jako wartość (first-class function) → ex01

def apply_twice(f, x):
    return f(f(x))

apply_twice(math.sqrt, 16.0)  # 2.0
fs = [math.sin, math.sqrt]
[f(1.0) for f in fs]

Funkcja jest obiektem: nazwa jest z nim związana tak samo, jak nazwa listy z listą. Można go przekazać jako argument, umieścić na liście i zwrócić jako wynik innej funkcji. Funkcja, która przyjmuje lub zwraca funkcje, to funkcja wyższego rzędu (higher-order function).

Domknięcie (closure) → ex01

def make_power(n):
    def power(x):
        return x ** n  # n: enclosing scope
    return power

square = make_power(2)
square(3.0)  # 9.0

Funkcja wewnętrzna zachowuje dostęp do zmiennych funkcji otaczającej także po jej zakończeniu; każde wywołanie make_power tworzy osobne domknięcie z własnym n.

Pułapka: odczyt zmiennej otaczającej nie wymaga deklaracji, ale przypisanie do niej (count += 1) tworzy zmienną lokalną; potrzebne jest wtedy nonlocal count.

Dekorator (decorator) → ex01

def timed(f):
    @wraps(f)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = f(*args, **kwargs)
        print(time.perf_counter() - start)
        return result
    return wrapper
@timed  # the same as: g = timed(g)
def g(n):
    return sum(range(n))

Dekorator to funkcja, która przyjmuje funkcję i zwraca funkcję; zapis @timed nad definicją jest skrótem przypisania g = timed(g). functools.wraps przenosi nazwę i dokumentację g na wrapper. Dekorator z parametrem (@repeat(3)) ma jeden poziom więcej: dopiero repeat(3) zwraca dekorator.

Iterator (iterator protocol) → ex06

class Countdown:
    def __init__(self, n): self.n = n
    def __iter__(self): return self
    def __next__(self):
        if self.n == 0: raise StopIteration
        self.n -= 1
        return self.n + 1

it = iter(Countdown(3))  # calls __iter__
next(it), next(it), next(it)  # 3, 2, 1
next(it, "end")  # StopIteration -> "end"

Obiekt iterowalny (iterable) zwraca z __iter__ iterator; jego __next__ daje kolejne elementy, StopIteration kończy ciąg. Pętla for wykonuje dokładnie to; tak samo zip, enumerate i DataLoader w PyTorch. Lista nie jest iteratorem: jej __iter__ zwraca nowy obiekt, więc można ją przejść wielokrotnie.

Generator (generator, yield) → ex06

def taylor_terms(x):
    term, k = 1.0, 0
    while True:
        yield term
        k += 1
        term *= x / k

list(islice(taylor_terms(1.0), 4))

Funkcja, której ciało zawiera yield, jest funkcją tworzącą generator (generator function): jej wywołanie nie uruchamia jeszcze żadnej instrukcji, lecz zwraca generator, czyli iterator, którego każde next wykonuje kod do najbliższego yield i zawiesza funkcję z jej zmiennymi. Elementy powstają na żądanie (leniwe wartościowanie, lazy evaluation, w Haskellu domyślne), więc ciąg może być nieskończony; islice pobiera jego początek.

Pułapka: generator można przejść tylko raz: w drugiej pętli next od razu zgłasza StopIteration.

Adnotacje typów (type annotations) → ex06

from collections.abc import Callable
Function = Callable[[float], float]

def compose(f: Function,
            g: Function) -> Function:
    return lambda x: f(g(x))

compose(math.sqrt, abs)(-16.0)  # 4.0
h = compose("not a function", abs)  # ok
# h(1.0): TypeError, 'str' not callable

Adnotacja (f: Function przy parametrze, -> Function przy wyniku) jest metadaną zapisaną w __annotations__; interpreter jej nie sprawdza, więc błąd typu ujawnia się dopiero przy wywołaniu h(1.0). Sprawdzają je narzędzia statycznej kontroli typów (static type checkers, np. mypy), a dataclass odczytuje je, by wygenerować pola klasy. Callable[[float], float]: funkcja z argumentem float zwracająca float.

B. Różniczkowanie numeryczne

Iloraz różnicowy (difference quotient) → ex02

f'(x) \approx \frac{f(x+h) - f(x)}{h} \approx \frac{f(x+h) - f(x-h)}{2h}

def central_difference(f, x, h):
    return (f(x + h) - f(x - h)) / (2 * h)

central_difference(math.sin, 1.0, 1e-5)
math.cos(1.0)  # the exact value

Pochodna to nachylenie stycznej. Iloraz różnicowy to stosunek przyrostu wartości funkcji f(x+h) - f(x), zwanego różnicą skończoną (finite difference), do przyrostu argumentu h; jest on nachyleniem siecznej. Iloraz centralny (sieczna przez x_0 - h i x_0 + h) ma rząd 2, iloraz w przód (forward difference) rząd 1 (karta „Rząd metody”), więc dla małego h nachylenie siecznej centralnej jest zwykle bliższe nachyleniu stycznej; dla konkretnej funkcji i konkretnego h nie jest to gwarantowane.

Dwa błędy: obcięcia i zaokrągleń (truncation, rounding error) → ex02

exact = math.cos(1.0)
for k in range(1, 17):
    h = 10.0 ** -k
    d = central_difference(math.sin, 1.0, h)
    print(h, abs(d - exact))

Błąd obcięcia to reszta wzoru Taylora, czyli suma pominiętych wyrazów; dla małego h dominuje w niej pierwszy z nich, h f''/2 dla różnicy w przód i h^2 f'''/6 dla centralnej (karta „Rząd metody”), więc błąd maleje jak h albo h^2; błąd zaokrągleń rośnie jak \varepsilon / h, bo odejmowanie bliskich liczb traci cyfry, a dzielenie przez małe h ten ubytek powiększa. Krok optymalny wynika z równowagi obu błędów: około \sqrt{\varepsilon} \approx 10^{-8} dla różnicy w przód i \sqrt[3]{\varepsilon} \approx 10^{-5} dla centralnej (\varepsilon \approx 2{,}2 \cdot 10^{-16}).

Pułapka: h = 10^{-10} nie jest „dokładniejsze”: błąd jest wtedy o kilka rzędów większy niż przy h = 10^{-5}.

Rząd metody (order of accuracy) → ex02

\frac{f(x+h) - f(x)}{h} = f'(x) + \frac{h}{2}\,f''(x) + \dots

\frac{f(x+h) - f(x-h)}{2h} = f'(x) + \frac{h^2}{6}\,f'''(x) + \dots

e1 = abs(central_difference(f, x, 1e-2) - d)
e2 = abs(central_difference(f, x, 1e-3) - d)
math.log(e1 / e2) / math.log(10)  # about 2

Rząd p oznacza błąd obcięcia O(h^p): potęga h w pierwszym pominiętym wyrazie rozwinięcia Taylora, który dla małego h dominuje w reszcie; dziesięciokrotnie mniejszy krok daje błąd 10^p razy mniejszy. Odczytuje się go z nachylenia prawej gałęzi wykresu błędu albo z ilorazu dwóch błędów. Różnica w przód ma rząd 1, centralna 2, bo w jej rozwinięciu wyraz z f'' się znosi.

Szereg Taylora i utrata cyfr znaczących (Taylor series, catastrophic cancellation) → ex02

e^x = \sum_{k=0}^{\infty} \frac{x^k}{k!}

def taylor_exp(x, n):
    total, term = 0.0, 1.0
    for k in range(1, n + 1):
        total += term
        term *= x / k
    return total + term

taylor_exp(-20.0, 100)     # 6.1e-09: wrong
1 / taylor_exp(20.0, 100)  # 2.06e-09

Składniki x^k/k! rosną co do wartości bezwzględnej, dopóki k < |x| (każdy jest poprzednim razy x/k, wiersz term *= x / k), więc liczba wyrazów potrzebnych do małego błędu obcięcia rośnie z |x|. Dla x = -20 duże składniki o przemiennych znakach znoszą się do bardzo małego wyniku, a ich błędy zaokrągleń zostają i przewyższają wynik (utrata cyfr znaczących); nie pomaga ani więcej wyrazów, ani dokładniejsze sumowanie. Pomaga przekształcenie wzoru: e^{-20} = 1/e^{20}, bo szereg dla e^{20} ma same składniki dodatnie. Ta sama zasada wraca w lab09: entropię krzyżową liczy się na logitach, a nie na prawdopodobieństwach.

C. Klasy

Metody specjalne (special methods, dunder) → ex03

class Vec:
    def __init__(self, x, y): ...
    def __add__(self, other): ...  # u + v
    def __rmul__(self, k): ...     # 2 * u
    def __abs__(self): ...         # abs(u)
    def __repr__(self): ...        # print(u)
    def __iter__(self): ...        # x, y = u

Operatory, funkcje wbudowane i pętla for wywołują metody o nazwach z podwójnym podkreśleniem; własny typ zyskuje dzięki nim składnię liczb, a z __iter__ także iterację (for c in u, x, y = u; protokół iteratora: karta „Iterator”). Bez __eq__ porównanie == sprawdza tożsamość obiektów, bez __repr__ print pokazuje adres.

Pułapka: metoda bez sprawdzenia typu argumentu przyjmie każdy obiekt, dla którego jej ciało się wykona: u * v dla wektorów może zwrócić wektor wektorów zamiast błędu.

Klasa danych (data class) → ex03

@dataclass(frozen=True)
class Vec:
    x: float
    y: float

    def __abs__(self):
        return math.hypot(self.x, self.y)

Vec(3.0, 4.0) == Vec(3.0, 4.0)  # True
{Vec(3.0, 4.0)}                 # hashable

@dataclass generuje z listy pól __init__, __repr__ i __eq__; frozen=True blokuje zmianę pól i dodaje __hash__, więc obiekt może być elementem zbioru i kluczem słownika; order=True dodaje porównania według kolejnych pól (porządek leksykograficzny krotki). Własne metody dopisuje się jak w zwykłej klasie.

Metoda odwrócona i NotImplemented (reflected method) → ex03

def __mul__(self, k):
    if not isinstance(k, (int, float)):
        return NotImplemented
    return Vec(self.x * k, self.y * k)

__rmul__ = __mul__  # 2 * v

Dla 2 * v interpreter wywołuje najpierw int.__mul__(2, v); wynik NotImplemented oznacza „nie obsługuję tego argumentu” i powoduje próbę metody odwróconej v.__rmul__(2), czyli wersji dla operandu po prawej stronie. Gdy obie zawiodą, powstaje TypeError. NotImplemented to wartość zwracana, NotImplementedError to wyjątek zgłaszany w niedokończonym kodzie.

D. Liczby dualne

Liczba dualna (dual number) → ex04

a = u,\; b = u',\; c = v,\; d = v' \;\Rightarrow\; ad + bc = uv' + u'v = (uv)'

@dataclass(frozen=True)
class Dual:
    real: float
    dual: float = 0.0

    def __mul__(self, o):
        return Dual(self.real * o.real,
                    self.real * o.dual
                    + self.dual * o.real)

Liczba dualna a + b\varepsilon: część rzeczywista a (real), część dualna b (dual); działania wynikają z samej algebry i \varepsilon^2 = 0. Gdy pary niosą wartość i pochodną (wzór), wynik działania też jest taką parą; dla sumy b + d = u' + v' = (u + v)'. Stała ma część dualną 0 (lift); metody odwrócone (__radd__, __rmul__) obsługują liczbę po lewej stronie operatora.

Pochodna z części dualnej (forward-mode automatic differentiation) → ex04

f(x + \varepsilon) = f(x) + f'(x)\,\varepsilon + \tfrac{1}{2} f''(x)\,\underbrace{\varepsilon^2}_{=\,0} + \dots

def derivative(f):
    return lambda x: f(Dual(x, 1.0)).dual

f = lambda x: (x + 2) * (x + 1)
f(Dual(3.0, 1.0))  # Dual(real=20.0, dual=9.0)
derivative(f)(3.0)  # 9.0

Podstawienie Dual(x, 1.0) wykonuje zwykły kod funkcji na liczbie x + \varepsilon. Ponieważ \varepsilon^2 = 0, ze wzoru Taylora zostają dwa pierwsze wyrazy: wynik to Dual(f(x), f'(x)). Współczynnik 1 przy \varepsilon daje w części dualnej samą pochodną; Dual(x, b) dałoby b\,f'(x) (karta „Reguła łańcuchowa”). Nie ma błędu obcięcia ani odejmowania bliskich liczb; zostaje błąd zaokrągleń kilku działań.

Reguła łańcuchowa (chain rule) → ex04

f(a + b\varepsilon) = f(a) + f'(a)\, b\, \varepsilon

def sin(x):
    if not isinstance(x, Dual):
        return math.sin(x)
    return Dual(math.sin(x.real),
                math.cos(x.real) * x.dual)

derivative(sin)(0.0)  # 1.0

Funkcja elementarna na liczbie dualnej mnoży własną pochodną (\cos a) przez część dualną argumentu (b), która niesie pochodną wszystkiego, co było wcześniej. Przyjmowanie float i Dual przez tę samą funkcję pozwala używać jednego kodu do obliczeń i do różniczkowania; tak samo działają NumPy i PyTorch.

Trzy sposoby obliczenia pochodnej → ex04

g = lambda x: sin(x) * exp(-x)
x0, h = 1.5, 1e-5
exact = (cos(x0) - sin(x0)) * exp(-x0)
abs((g(x0 + h) - g(x0 - h)) / (2 * h) - exact)
abs(derivative(g)(x0) - exact)

Wzór analityczny wymaga ręcznego wyprowadzenia; różnica centralna wymaga tylko wartości funkcji, ale ma błąd obcięcia i zaokrągleń (10^{-12} przy optymalnym h); liczba dualna wymaga, by kod funkcji działał na typie Dual, i daje wynik dokładny co do zaokrągleń (10^{-17}). Tryb w przód (forward mode) oblicza jedną pochodną cząstkową na przebieg; tryb wsteczny (reverse mode, torch.autograd) oblicza cały gradient w jednym przebiegu.

E. Wyjątki, menedżery kontekstu i testy

Wyjątki (exceptions) → ex05

try:
    value = float(text)
except ValueError as err:
    raise ValueError("bad input") from err
else:
    print(value)  # only if try raised nothing
finally:
    print("always")

except E przechwytuje E i jej podklasy (ArithmeticError obejmuje ZeroDivisionError i OverflowError); else wykonuje się tylko wtedy, gdy blok try nie zgłosił wyjątku, finally zawsze. Własny wyjątek to podklasa (class DomainError(ValueError)); raise … from err zachowuje przyczynę w __cause__.

Pułapka: except: bez klasy i except Exception: ukrywają także błędy programisty.

Menedżer kontekstu (context manager, with) → ex05

@contextmanager
def timer():
    start = time.perf_counter()
    try:
        yield  # paused during the with block
    finally:
        print(time.perf_counter() - start)

with timer():  # prints the time of the block
    sum(range(10**6))

Menedżer kontekstu to obiekt z metodami __enter__ i __exit__: with wywołuje pierwszą na wejściu do bloku, drugą na wyjściu, także po wyjątku (__exit__ zwracające False przekazuje go dalej). Takim obiektem jest plik z open: po bloku with jest zamknięty. Dekorator @contextmanager zamienia funkcję tworzącą generator w menedżer kontekstu: kod przed yield wykonuje się na wejściu do bloku with, kod po yield na wyjściu z niego; finally zapewnia, że ten drugi wykona się także po wyjątku.

Test w pytest → ex07

def test_division():
    d = derivative(lambda x: 1 / x)
    assert d(2.0) == pytest.approx(-0.25)

def test_division_by_zero():
    with pytest.raises(ZeroDivisionError):
        Dual(1.0, 1.0) / Dual(0.0, 1.0)

pytest zbiera funkcje test_* z plików test_*.py (albo z pliku podanego jawnie), wykonuje każdą osobno i raportuje nieudane assert z wartościami obu stron. pytest.approx porównuje liczby zmiennoprzecinkowe z tolerancją, pytest.raises sprawdza, że blok zgłasza wyjątek, parametrize powtarza test dla listy wartości. Zadania domowe są sprawdzane w ten sam sposób: zestawem testów uruchamianych przez pytest.
